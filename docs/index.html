Why openfal

Built for developers who want local endpoints, not workflow plumbing.

openfal sits between hosted APIs and node-graph workstations: familiar client ergonomics, pre-wired local checkpoints, and a single CLI lifecycle.

01 / API COMPATIBILITY

Drop-in fal-style API & SDK

Exposes fal-compatible route names, /queue/* submission, SSE status streaming, and a fal_client-style Python SDK (openfal.subscribe, run, submit, upload_file).

Scope: Covers supported local models only—does not claim full hosted fal.ai catalog or moderation parity.
02 / ZERO NODE GRAPHS

No ComfyUI GUI or graph UX

Consumes supported Comfy-Org single-file FP8/INT8 checkpoints under the hood and verifies supporting assets (encoders, VAEs, and Wan Animate's 403 CLIP/pose/SAM2 files) behind fixed HTTP routes and Studio.

Trade-off: Fixed, verified endpoints instead of arbitrary custom node-graph composability.
03 / UNIFIED CLI

One CLI beyond just serving

detect, autosetup, download (including --runtime-assets-only repair), models, cleanup, and serve live in one tool—no manual weight hunting.

Unlike LLM engines such as vLLM (continuous batching, multi-GPU TP), openfal is a serialized PyTorch block-offloading runner.
Quickstart

From clone to local Studio in three steps.

Requires Python 3.10+ and a PyTorch build matching your compute device. Model files stay on the server host; any machine on your network can call the API.

STEP 1 · INSTALL & DETECT

Install CUDA PyTorch & openfal

git clone https://github.com/esokullu/openfal.git
cd openfal
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -e ".[inference]"
openfal detect

Install CUDA PyTorch first on Windows/Linux NVIDIA GPUs (macOS/CPU can skip the index-url line).

STEP 2 · DOWNLOAD WEIGHTS

Pick a tier or component

openfal autosetup --dry-run
openfal autosetup --tier minimal -y

Or target a model directly with openfal download --component qwen_image_21 --quant fp8_e4m3.

STEP 3 · SERVE

Start API, queue & Studio

openfal serve --port 8008

Binds 127.0.0.1 by default. For LAN access, pass --host 0.0.0.0 --api-key <secret>. Open http://127.0.0.1:8008/ for Studio or /docs for OpenAPI.

API & SDK

Call local endpoints like fal.ai.

Use the Python SDK, direct synchronous POSTs, or queued requests with status polling and Server-Sent Events. 

import openfal

server = "http://127.0.0.1:8008"
reference = openfal.upload_file("portrait.png", base_url=server)
result = openfal.subscribe(
    "qwen/image-2.1/edit",
    arguments={
        "prompt": "Keep the person recognizable and change the lighting to warm evening light",
        "reference_image_urls": [reference],
        "resolution": "768P",
        "aspect_ratio": "1:1",
        "seed": 20261117,
    },
    base_url=server,
)
print(result["images"][0]["url"])
import openfal

server = "http://127.0.0.1:8008"
identity = openfal.upload_file("character.png", base_url=server)
driver = openfal.upload_file("performance.mp4", base_url=server)
result = openfal.subscribe(
    "wan/v2.2/animate",
    arguments={
        "prompt": "The reference character follows the driving performance naturally",
        "face_image_url": identity,
        "driving_video_url": driver,
        "resolution": "480P",
        "duration": 3,
        "fps": 16,
        "seed": 20261117,
    },
    base_url=server,
)
print(result["video"]["url"])
curl -X POST http://127.0.0.1:8008/qwen/image-2.1/text-to-image \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "A golden poodle running on an Istanbul cobblestone street",
    "resolution": "768P",
    "aspect_ratio": "16:9",
    "seed": 20261117
  }'
# Submit to queue (returns request_id, status_url, response_url, cancel_url)
curl -X POST http://127.0.0.1:8008/queue/wan/v2.2/text-to-video \
  -H "Content-Type: application/json" \
  -d '{"prompt":"A dog walking down a quiet street","resolution":"480P","duration":2,"seed":20261117}'

# Optional: stream live status updates via SSE
curl -N http://127.0.0.1:8008/wan/v2.2/text-to-video/requests/<request_id>/status/stream

Verified engineering limits to know before deploying

  • Single compute device: Runners execute on logical cuda:0 (or MPS/CPU fallback). Profiles named dual_* are memory-planning configs and do not perform multi-GPU tensor parallelism.
  • Profile telemetry is estimated: Studio's block map and /v1/engine/status report profile estimates (telemetry_kind: "profile_estimate"), not live hardware measurements.
  • macOS status: MPS and CPU fallback branches have host regression coverage, but actual Apple Silicon inference and unified-memory headroom have not been benchmarked yet.
  • Local trust boundary: Binds 127.0.0.1 by default with an in-memory queue (lost on restart). Pass --api-key (or set OPENFAL_API_KEY) whenever exposing --host 0.0.0.0 on a LAN.

Precision & configuration notes across engines

  • Alibaba models: vLLM-Omni runs dequantized BF16 checkpoints with online --quantization fp8 (and --enable-cpu-offload on Wan 2.2), winning qwen21_t2i (2.45 s) and wan22_i2v_14b (75.58 s). openfal uses native INT8 ConvRot / FP8 scaled Tensor Core GEMMs + cuDNN SDPA priority, beating ComfyUI on qwen21_t2i (3.98 s vs 5.32 s) and cutting wan22_i2v_14b to 109.14 s at 19.3 GB VRAM (12 GB less than ComfyUI).
  • MiniMax-H3 models: openfal wins minimax_h3_t2i (3.47 s vs ComfyUI 3.83 s, 18.7× faster than vLLM-Omni) and runs within 9% of ComfyUI on minimax_h3_i2v (52.78 s vs 48.34 s, 2.2× faster than vLLM-Omni) using 4.5–4.7 GB less VRAM than ComfyUI. vLLM-Omni streams dequantized BF16 weights via DistributedLayerwiseOffloadBackend (--dlo-resident-layers 12, 14.2–16.3 GB VRAM), where PCIe H2D transfer dominates latency.
  • FL2VA duration floor: openfal and ComfyUI generate 73 frames (3.04 s at 24 fps); vLLM-Omni requires at least 4 s, receives num_frames=97, and outputs 107 frames (4.46 s) with 32 kHz stereo AAC audio.
